# Grundbausteine der Objektorientierten Programmierung

> [!abstract] Kernaussage
> Eine **Klasse** ist der Bauplan, ein **Objekt** die daraus erzeugte Instanz. Die Klasse legt mit ihren **Datenfeldern** fest, *was* ein Objekt weiss (sein Zustand), und mit ihren **Methoden**, *was* es kann (sein Verhalten); der **Konstruktor** bringt ein neues Objekt in einen gültigen Anfangszustand. Ein laufendes Programm ist nichts anderes als eine Menge von Objekten, die sich gegenseitig Methoden aufrufen.

## Lernziele

- Sie kennen und verstehen einige grundlegende Konzepte der objektorientierten Programmierung: Klassen & Objekte, Erzeugung von Objekten, Methoden mit Parametern und Aufrufergebnissen, Zustand eines Objekts, Interaktion zwischen Objekten.
- Sie kennen die Datentypen `int`, `String` und `boolean` und verstehen deren Eigenschaften.
- Sie können die BlueJ (oder eine andere) Entwicklungsumgebung verwenden, um Objekte zu erzeugen und mit ihnen zu interagieren.

## Theorie

### Warum objektorientiert programmieren?

- OOP ist der **Industriestandard** – Java, C#, C++, Python, Swift sind alle objektorientiert.
- OOP ist ein **Werkzeug gegen Komplexität**: ein grosses Problem wird in viele kleine, je für sich verständliche Bausteine zerlegt.
- Jeder Baustein ist für genau eine Sache zuständig und versteckt seine Interna. Wer ihn benutzt, muss nur wissen *was* er tut, nicht *wie*.

> [!note] Merkhilfe
> Ein Objekt ist eine Kapsel aus **Daten + zugehörigem Verhalten**. Genau das unterscheidet OOP von der prozeduralen Programmierung, wo Daten und Funktionen getrennt herumliegen.

### Objekte und Klassen

Objektorientiert programmieren heisst: Während der Laufzeit entstehen **Objekte**, die miteinander interagieren. Was für Objekte das sind, hängt vom Programm ab – in einem Zeichenprogramm Kreis, Quadrat und Dreieck, in einer Verkehrssimulation Auto, Velo und Fussgänger.

Der Programmierer schreibt den Code für gleichartige Objekte **genau einmal**. Dieser Code ist die **Klasse** – das Template bzw. der Bauplan.

- Aus einer Klasse lassen sich **beliebig viele** Objekte erzeugen.
- Jedes Objekt hat **eigene Werte** für dieselben Eigenschaften: ein Auto fährt 185 km/h, ein anderes 130 km/h.
- Die **Methoden** beschreiben das Verhalten, das alle Objekte dieser Klasse beherrschen.

| | Klasse | Objekt (Instanz) |
|---|--------|------------------|
| Was | Bauplan, Quellcode | konkretes Exemplar zur Laufzeit |
| Wie viele | einmal geschrieben | beliebig viele |
| Wann | zur Schreibzeit | zur Laufzeit, per `new` |
| Beispiel | `Auto` | das rote Auto mit 185 km/h |

> [!example] Objekt erzeugen
> ```java
> Auto meinAuto = new Auto("rot", 185);
> ```
> `new Auto(...)` ruft den Konstruktor auf und liefert das fertige Objekt zurück. `meinAuto` ist nur der Name, unter dem wir es ansprechen.

### Naming Conventions

Java erzwingt das nicht – aber es ist verbindliche Konvention und wird bewertet.

| Element | Schreibweise | Beispiel |
|---------|--------------|----------|
| Klasse | `UpperCamelCase`, Substantiv, **Einzahl** | `Ticketautomat` |
| Methode | `lowerCamelCase`, Verb | `geldEinwerfen()` |
| Parameter | `lowerCamelCase` | `betrag` |
| Datenfeld | `lowerCamelCase` | `ticketPreis` |
| Konstante | `UPPER_SNAKE_CASE` | `MAX_PREIS` |

Erlaubte Zeichen im Namen: Buchstaben, Ziffern und `_` – **kein `-`**, und nie mit einer Ziffer beginnen.

### Datentypen

| Typ | Art | Inhalt | Wertebereich / Beispiel | Default |
|-----|-----|--------|--------------------------|---------|
| `int` | primitiv | Ganzzahl | $-2^{31}$ bis $2^{31}-1$ (ca. ±2,1 Mrd.) | `0` |
| `boolean` | primitiv | Wahrheitswert | nur `true` oder `false` | `false` |
| `String` | Referenztyp | Text | `"Hallo"` | `null` |

> [!warning] Typische Fallen
> - **`boolean` ist in Java kein 0/1.** Anders als in C gibt es keine automatische Umwandlung – `if (1)` ist ein Compiler-Fehler, es muss `if (x == 1)` heissen.
> - **`String` ist kein primitiver Typ**, sondern eine Klasse. Vergleiche darum mit `a.equals(b)` und **nicht** mit `a == b` – `==` vergleicht bei Referenztypen die Adresse, nicht den Inhalt.
> - **`int` läuft still über.** `2147483647 + 1` ergibt `-2147483648`, ohne Fehlermeldung.
> - **Ganzzahldivision schneidet ab:** `7 / 2` ist `3`, nicht `3.5`.

### Zustand eines Objekts

Der **Zustand** eines Objekts ist die Gesamtheit der Werte in seinen Datenfeldern (auch *Attribute*, *Instanzvariablen* genannt). Jedes Datenfeld hat einen festen Datentyp.

- **Welche** Datenfelder es gibt, gibt die Klasse vor – inklusive ihrer Anfangswerte.
- **Welche Werte** darin stehen, ist von Objekt zu Objekt verschieden.
- Ein Methodenaufruf kann diese Werte verändern – das Objekt wechselt seinen Zustand.

Aufruf einer Methode auf einem Objekt:

```java
objektName.methodenName(parameter);
```

> [!example] Zustandsänderung
> ```java
> automat.geldEinwerfen(500);   // Zustand: guthaben 0 → 500
> automat.ticketDrucken();      // Zustand: guthaben 500 → 0, gesamtsumme 0 → 500
> ```

### Aufbau einer Klasse

Eine Klasse besteht aus **Kopf** und **Innenteil**:

```java
public class Ticketautomat        // ← Kopf
{                                 // ← Beginn Innenteil
    private int ticketPreis;      // Datenfelder
    private int guthaben;

    public Ticketautomat(int preis)   // Konstruktor
    {
        ticketPreis = preis;
        guthaben = 0;
    }

    public void geldEinwerfen(int betrag)   // Methode
    {
        guthaben = guthaben + betrag;
    }
}
```

| Bestandteil | Aufgabe |
|-------------|---------|
| `public` | Die Klasse ist im ganzen Programm sichtbar |
| `class` | Schlüsselwort: hier beginnt eine Klasse |
| **Datenfelder** | speichern die Daten **im** Objekt → Zustand |
| **Konstruktor** | setzt das Objekt auf einen gültigen Anfangszustand |
| **Methoden** | implementieren das Verhalten des Objekts |

Regeln für den Klassennamen: **Einzahl**, beginnt mit **Grossbuchstaben**, ist ein **Substantiv** und möglichst **prägnant**.

### Datenfelder

- Werden so gewählt, dass das Objekt seine Aufgabe sinnvoll erfüllen kann.
- Können über die ganze Lebensdauer **konstant** bleiben oder sich zur Laufzeit **ändern**.
- Haben **immer** einen Datentyp.
- `private` bedeutet: nur **innerhalb** der Klasse sichtbar, von aussen nicht erreichbar.

> [!important] Warum `private`?
> Datenfelder sind grundsätzlich `private` (**Datenkapselung**). Nur so kann die Klasse garantieren, dass ihr Zustand gültig bleibt – z. B. dass `guthaben` nie negativ wird. Wer von aussen direkt schreiben dürfte, könnte diese Zusicherung jederzeit brechen. Zugriff von aussen läuft deshalb über Methoden.

### Konstruktor

Der Konstruktor ist einer Methode sehr ähnlich, mit drei Unterschieden:

1. Er heisst **exakt gleich wie die Klasse** (inkl. Grossschreibung).
2. Er hat **keinen Ergebnistyp** – auch kein `void`. Das Ergebnis des `new`-Aufrufs ist das neue Objekt selbst.
3. Er wird **nur einmal** ausgeführt, nämlich bei `new`.

Typischerweise ist er `public` und lädt seine Parameterwerte in die Datenfelder:

```java
public Ticketautomat(int preis)
{
    ticketPreis = preis;   // Parameter → Datenfeld
    guthaben = 0;
}
```

> [!warning] Parameter leben kürzer als Datenfelder
> Parameter und lokale Variablen existieren nur während der **Ausführung** von Konstruktor bzw. Methode. Danach sind sie weg. Was das Objekt sich *merken* soll, muss deshalb in ein **Datenfeld** geschrieben werden – genau das tut der Konstruktor.

### Methoden

Methoden sind der Weg, mit einem Objekt zu interagieren.

```java
public void geldEinwerfen(int betrag)   // ← Kopf
{                                       // ← Rumpf
    guthaben = guthaben + betrag;
}
```

- `void` = die Methode gibt **kein** Ergebnis zurück.
- Statt `void` kann ein Ergebnistyp stehen (`int`, `String`, `boolean`, …) – dann **muss** die Methode ein `return` enthalten.
- Null, ein oder mehrere Parameter, durch Komma getrennt.
- Die Methode endet am Ende des Rumpfes **oder** sofort bei einem `return`.

**Zwei Arten von Methoden:**

| Art | Zweck | Erkennungsmerkmal | Beispiel |
|-----|-------|-------------------|----------|
| **Sondierende** Methode (*accessor*) | gibt Information zurück, ändert den Zustand nicht | Ergebnistyp ≠ `void`, oft `get…` | `public int getGuthaben()` |
| **Verändernde** Methode (*mutator*) | ändert den Zustand des Objekts | meist `void`, oft `set…` | `public void geldEinwerfen(int betrag)` |

### Signatur einer Methode

Die **Signatur** ist der Kopf ohne Rumpf – Name plus Parameterliste. Sie ist das, was ein Benutzer der Klasse kennen muss.

```java
public String getName();
public String getName(String anrede);
```

Beide dürfen nebeneinander existieren: gleicher Name, **unterschiedliche Parameterliste** = **Überladen** (*overloading*). Der Ergebnistyp allein reicht dafür **nicht** aus.

### Interaktion zwischen Objekten

In einem fertigen Java-Programm rufen die Objekte ihre Methoden **gegenseitig selbst** auf – nicht wir von Hand. In BlueJ übernehmen wir diese Rolle ausnahmsweise per Rechtsklick, um einzelne Objekte auszuprobieren.

```text
    ┌──────────────┐  geldEinwerfen(500)   ┌────────────────┐
    │   Kunde      │ ────────────────────▶ │ Ticketautomat  │
    │              │ ◀──────────────────── │                │
    └──────────────┘    getGuthaben()      └────────────────┘
                          → 500
```

### Arbeiten mit BlueJ

| Schritt | Vorgehen |
|---------|----------|
| Objekt erzeugen | Rechtsklick auf die Klasse → `new Klassenname(...)`, Parameter eingeben |
| Objekt ablegen | erscheint als rote Box auf der **Object Bench** |
| Methode aufrufen | Rechtsklick auf das Objekt → Methode wählen |
| Zustand ansehen | Rechtsklick → *Inspect* zeigt alle Datenfelder mit ihren aktuellen Werten |
| Schraffierte Klasse | Klasse ist noch nicht kompiliert → *Compile* |

> [!note] Warum BlueJ?
> BlueJ macht Objekte **sichtbar und anfassbar**, ohne dass zuerst eine `main`-Methode geschrieben werden muss. Genau darum wird es im ersten Semester eingesetzt.

### Kommentare

```java
// Einzeiliger Kommentar

/*
   Mehrzeiliger Kommentar
*/

/**
 * Javadoc-Kommentar – beschreibt, was die Methode tut.
 * @param betrag  der eingeworfene Betrag in Rappen
 * @return        das aktuelle Guthaben
 */
public int geldEinwerfen(int betrag)
{
    guthaben = guthaben + betrag;
    return guthaben;
}
```

> [!important] Kommentare sind Teil der Codequalität
> Sie erklären das **Warum**, nicht das **Was**. `guthaben = guthaben + betrag; // addiert betrag zu guthaben` ist wertlos. Javadoc (`/** … */`) über Klasse, Konstruktor und jeder öffentlichen Methode ist der Standard – laut Modulbeschreibung ([[PROG1#Themen]]) wird verständlicher und wartbarer Code bewertet.

## Begriffe

| Begriff | Bedeutung |
|---------|-----------|
| Klasse | Bauplan / Template für gleichartige Objekte |
| Objekt / Instanz | Zur Laufzeit aus einer Klasse erzeugtes Exemplar |
| `new` | Operator, der ein Objekt erzeugt und den Konstruktor aufruft |
| Datenfeld / Attribut / Instanzvariable | Variable **im** Objekt, speichert den Zustand |
| Zustand | Gesamtheit der aktuellen Werte aller Datenfelder eines Objekts |
| Methode | Implementiert das Verhalten eines Objekts |
| Konstruktor | Methodenähnlich, heisst wie die Klasse, kein Ergebnistyp, setzt den Anfangszustand |
| Parameter | Eingabewert einer Methode; lebt nur während deren Ausführung |
| Signatur | Kopf einer Methode: Name + Parameterliste |
| Überladen (*overloading*) | Gleicher Methodenname, unterschiedliche Parameterliste |
| Sondierende Methode (*accessor*) | Gibt Information zurück, ändert nichts |
| Verändernde Methode (*mutator*) | Ändert den Zustand des Objekts |
| Datenkapselung | Datenfelder `private`, Zugriff nur über Methoden |
| `public` | Von überall im Programm sichtbar |
| `private` | Nur innerhalb der eigenen Klasse sichtbar |
| `void` | Ergebnistyp für „gibt nichts zurück“ |
| `return` | Liefert das Ergebnis zurück und beendet die Methode sofort |
| Primitiver Typ | `int`, `boolean`, … – enthält den Wert direkt |
| Referenztyp | `String`, eigene Klassen – enthält eine Referenz auf das Objekt |
| Object Bench | BlueJ-Bereich, in dem erzeugte Objekte abgelegt werden |
